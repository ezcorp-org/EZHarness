  through W03's stop path, and no operation was journaled.
- Run A: the package was quarantined while its guest ran, and the server was SIGKILLed mid-stop. The
  run was cancelled once with factory_package_quarantined and is in W02c's affected-run record.
- Both runs stayed "cancelling". Both reservations stayed "uncertain" with no settlement. The server
  logged "factory_usage_hold_unresolved: no-operation-receipt" on every pass.
- The inbox shows attempt-stopped uncertain:true twice: the real stop first timed out, then confirmed.
The first attempt hit the ordinary-store outage (Exited 137) and is kept as proof/readiness-failure-base.json.

ROOT CAUSE
1. FactoryTaskStops.finalize treated "no terminal usage" as "unknown usage" without consulting the
   journal, so a stop before the first operation always left an uncertain hold. Reconciliation can
   only resolve a hold from an operation's provider receipt, and there was none.
2. The kernel folds a later certain attempt-stopped into an attempt it holds as stopped-and-uncertain
   only when the event says uncertain:false explicitly. No product path emitted that, so even a late
   stop receipt never cleared the attempt.

FIX
- confirm() reads the journal through its public API before the finalize transaction. The set is
  final: the sealed stop exists, so cancellation was accepted, and prepare() refuses any attempt that is
  not admitted or running.
- If there is no terminal usage and the journal is empty, finalize settles in the same transaction:
  - a settlement with source "no-operations", knownCostMicros "0", and the signed stopReceiptDigest;
  - exactly one usage-settled event;
  - FactoryBudgets.settleWithoutOperationsInTransaction: zero cost and zero tokens, with compute
    charged at the reserved bound because a killed process reports no measured compute;
  - a certain stop event.
- Any journaled operation, even one only prepared, keeps the uncertain-hold path.
- A certain stop after a stop-uncertain event carries uncertain:false. The stored event's certainty is
  re-derived from the typed settlement.
- Migration add-factory-usage-no-operations: adds the source value and a stop_receipt_digest column.
  Its CHECKs allow a stop receipt on that source only, and only as a known zero with nothing held and
  no provider receipt. It has a schema mirror, a restart case, and coverage threshold 100.
