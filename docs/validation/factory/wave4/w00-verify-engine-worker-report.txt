Deliverable 1 — scripts/lib/container-engine.ts
------------------------------------------------
Exports:
  - resolveEngine(env, hasCommand) -> "podman" | "docker"
    Same rule as scripts/lib/container-engine.sh, in order:
      1. EZCORP_CONTAINER_ENGINE wins if set (validated to podman|docker,
         and must be present on hasCommand).
      2. CI set + docker present -> docker.
      3. podman present -> podman.
      4. docker present -> docker.
      5. else throws NoContainerEngineError.
    Named errors: InvalidContainerEngineError, ContainerEngineNotFoundError,
    NoContainerEngineError — messages match the shell script's stderr text.
  - resolveComposeDockerHost(engine, env, uid, socketExists) -> string | undefined
    Docker: passes through any already-set DOCKER_HOST untouched (undefined
    if unset). Podman: honours an already-exported DOCKER_HOST untouched;
    otherwise builds /run/user/<uid>/podman/podman.sock and returns
    `unix://<path>`; if that socket does not exist, throws
    PodmanSocketNotFoundError (a named error) instead of guessing — this
    helper deliberately does NOT implement the shell resolver's macOS
    `podman machine inspect` fallback (documented in the file header as
    Linux-only, matching this repo's Bun tooling hosts).
  - hasCommandOnPath / isUnixSocket: production adapters (Bun.which / fs
    statSync) — both dependency-injected everywhere else so tests never
    touch the real PATH or filesystem.
Comment block above resolveEngine is verbatim-matched (same 4-point rule
text) to the header comment in scripts/lib/container-engine.sh so the two
cannot drift silently.

scripts/lib/container-engine.test.ts — 19 tests, 42 expect() calls, 0 fail.
Parity harness: for every required branch (EZCORP_CONTAINER_ENGINE set to
each value, an invalid value, CI+both->docker, CI+podman-only->podman,
developer+both->podman, developer+docker-only->docker, an engine named but
not installed, neither installed) it builds a stub $PATH directory, asks
`bash -c 'source scripts/lib/container-engine.sh && printf ...'` to resolve
against it AND asks resolveEngine() to resolve against the identical
directory via an injected hasCommand, and asserts they agree — plus two
extra cases (empty-string EZCORP_CONTAINER_ENGINE / CI treated as unset,
matching the shell's `[ -n ... ]` test). Separately covers every
resolveComposeDockerHost branch (docker no-op, docker passthrough, podman
honours preset DOCKER_HOST without probing a socket, podman builds the
uid-scoped socket path, podman throws PodmanSocketNotFoundError naming the
exact socket path and both remediation lines, empty-string DOCKER_HOST
treated as unset) and the two production adapters (hasCommandOnPath against
a real "bash" and a nonexistent name; isUnixSocket against a real listening
Bun.listen unix socket, a regular file, and a missing path).
