3. HUNKS READ
Defect 1 (re-grant):
- The migration allow-factory-artifact-regrant.ts adds grant_revision BIGINT NOT NULL DEFAULT 1, so existing
  rows become grant 1. It adds a CHECK grant_revision > 0. It rebuilds the primary key with grant_revision
  only while the old key shape is present, so a rerun keeps every constraint oid. It adds a partial unique
  index idx_factory_artifact_read_grants_active WHERE revoked_at IS NULL. migrate.ts appends it, and schema.ts
  mirrors it.
- Grant: it locks every row of the share. It refuses if any row is active. It inserts the next revision with
  ON CONFLICT DO NOTHING, and a lost race is refused by name. The audit entry carries grantRevision. A revoked
  row is never updated back to active.
- Revoke: it picks the active row first, else the latest one. It updates only that grant_revision. A repeated
  revoke writes nothing.
- Seal: revision 1 adds no key to the digested object, so a first grant seals byte for byte as before. Later
  revisions include grantRevision, so seals and audit ids never collide.
- The only other reader, loadSharedInTransaction, filters revoked_at IS NULL and needs exactly one row, so
  revoked history cannot shadow or add to an active grant.
Defect 2 (display names):
- grants.ts reads only `id, name` from users or service_accounts. It trims the name and cuts it at 256 code
  points. A blank name, a missing row, or a name equal to the id gives "Unnamed principal". The authorization
  path is unchanged.
- _shared.ts adds displayName to grantResource and to both mutation responses (via displayNameOf).
  FactoryGrantResource.displayName is required. The response schema requires 1 to 256 characters, and schema
  drift passes.
