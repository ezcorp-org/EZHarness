HOW EACH SPLIT WAS MADE
  By responsibility, never by line count, and always preserving the order of
  checks, the error codes, the messages, the paths, and the thrown types.
    validation.ts   one validator per schema keyword family, per JSON value kind,
                    per compiled node kind, per API resource family; compiled
                    factory becomes six ordered phases.
    compiler.ts     two named per-node passes behind the existing forEach
                    callbacks; compileFactory becomes six phases; expression
                    inference splits into logical and comparison families.
    schema.ts       keyword matching, then one matcher per JSON value kind.
    kernel.ts       applyRepair into admissibility, sealed revision, aggregate
                    scopes, affected nodes, pending record, partition
                    invalidations; advanceKernel's switch into applyEvent.
    workflow.ts     five phases; nothing new imported, no call added or
                    reordered, so the workflow stays deterministic.
    service.ts      body reader, dispatch table, start and reply handlers.
    podman.ts       input assertions, provisioned-path assertions,
                    typecheck-and-compile, feature tests.

  Two decisions worth naming:
   - validateSchemaNode's $ref arm returns the referenced node's verdict to the
     caller instead of returning outright, because a reference node still owes
     its own $defs walk. Returning early would silently drop that validation.
   - applyEvent is typed over DispatchedEvent, the event union minus the two
     kinds advanceKernel answers before the table, so the switch stays
     exhaustive without a default branch no run could reach and no test cover.
