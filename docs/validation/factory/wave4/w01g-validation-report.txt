3. THE SUPERVISOR FLAKE FIX (a805171a5)
---------------------------------------

Method: I used W16's shape, scaled up. The loop ran 20 rounds of 12 concurrent
processes. Each process ran the two bind tests of
src/factory/runner/supervisor-process.test.ts (filtered with -t). I ran it three
times: on the fixture before a805171a5, on the fixture after it, and on the
in-tree file. The old and new copies came from git show, with their relative
imports made absolute, and live in r4/flake/. Both copies pass all 38 tests
alone. The loop ran under flock --close. Script: repro/flake-loop.sh.

  fixture                  runs   red runs   failed tests
  old (a805171a5^)         240    63         65
  new (a805171a5)          240    0          0
  in-tree (f0aafe3a0)      240    0          0

Of the old failures, 57 were "a bind that fails degrades by name and is retried
on the next heartbeat". Six were "binds once after the first good probe".
Both are the tests the commit changed.

The fix is sound. Each test now stops on the fact it asserts: the third ready
record, or the first ready record after the retry. A heartbeat count shared
with the file-I/O observer no longer decides when it stops. The 1,000-heartbeat
cap is an upper bound only. If the asserted record never appears, the test
still fails on its own expectations.
