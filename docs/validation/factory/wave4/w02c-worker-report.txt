WHAT CHANGED
- The production stop seam is src/factory/package-fence.ts, class FactoryPackageFence.
  - It runs inside the quarantine or revoke transaction, which holds the installation write lock.
  - It cancels every run with a live attempt on the package. It uses the operator's own cancel, requestFactoryRunCancellationInTransaction, which was extracted from FactoryRunLifecycle.cancel with no change in behaviour.
  - The cancel carries the typed reason, factory_package_quarantined or factory_package_revoked.
  - The kernel answers with cancel-node, and W03's stop path settles it unchanged.
- Each affected attempt gets one sealed row in the new table factory_package_fence_runs.
  - preview() returns live attempts using the same query the fence acts on.
  - affectedRuns() reads the record, one page at a time.
- Refusals are typed. FactoryPackageBlockedError carries code, trustRevision and installationGeneration. It is raised:
  - at admission: FactoryNativeRunnerPolicy now reads current trust, and the production composition supplies the check;
  - at preflight;
  - at launch: the dispatcher's queue failure code is now the typed code.
- The trust store fails closed. A FactoryPackageTrusts without a fence refuses quarantine and revoke with factory_package_fence_unavailable.
- createFactoryPackageTrusts() composes the trust store the way the product must.

OPEN (interface questions)
1. W03 usage reconciliation.
   - Run A is cancelling with the typed reason and its guest is stopped, but the run never finishes.
   - Cause: the attempt was stopped before its first operation, so its budget hold stays uncertain. Reconciliation refuses it on every pass with factory_usage_hold_unresolved: no-operation-receipt.
   - An operator's cancel of a running attempt takes the same path.
   - Needed: a W03 settlement rule for a stopped attempt whose journal has no operations.
2. The orchestrator runs each effect once (retry maximumAttempts: 1 in workflow.ts).
   - A refused dispatch-node admission therefore fails the run's workflow, and the run stays running.
   - At base the same run was admitted, then denied at launch, and was equally stuck.
   - C05 says an affected run waits or fails explicitly.
   - Needed: a typed refusal path from an effect back to the kernel.
3. Freeze section 3 suggested a W03-owned second authority path for package stops, with lease-revoked as the physical stop reason.
   - The fence does not need that path: it consumes the existing cancel.
   - As a result, the host stop receipt reads cancelled. The typed reason lives on the run's stop reason and its error message.
4. W14's console still builds FactoryPackageTrusts without a fence, so after this merges its quarantine refuses with factory_package_fence_unavailable.
   - W14 was told on 2026-09-23 to use createFactoryPackageTrusts, and to use FactoryPackageFence.preview and affectedRuns.
   - Expect a small textual conflict in package-preparation.ts, in change().
5. C05 also blocks new acceptance and release claims. That belongs to the release fence (W09c/W09d) and is not done here.
