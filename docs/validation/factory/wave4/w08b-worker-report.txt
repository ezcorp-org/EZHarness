WHY

W09b found that S3FactoryManifestReleaseProfile needs Pick<FactoryMaterialService, "list">, and the
only implementation, FactoryAttemptMaterials, is bound to one attempt's authority at construction.
A production release.profiles composition builds its profile once and only later, at resolve() time,
learns which attempt an acceptance decision names -- so no such composition could ever be built.
This package closes that gap without widening authority.

WHAT CHANGED

src/factory/release-s3-scope.ts (W08's file; +56/-1 lines):
  Added FactoryVerifiedAttemptMaterials, implementing Pick<FactoryMaterialService, "list">.
  Attempt-agnostic at construction (takes {database, blobs, journal}, no bound attempt). On every
  call it:
    1. Snapshots the caller's FactoryMaterialScope.
    2. Reads the NAMED attempt's own current FactoryAttemptAuthority fresh, via
       FactoryExecutionJournal.readAuthorityInTransaction, keyed on the caller's exact
       tenant/project/run/attempt. An attempt the journal does not currently recognize under that
       exact scope returns undefined, refused as FactoryMaterialError("factory_material_scope_denied")
       before any material row is read.
    3. Delegates the actual listing to a freshly constructed FactoryAttemptMaterials under that
       authority -- W04's one query, scope check, and liveness rule; no second implementation.
  No edit to artifact-materials.ts (W04's file), release-s3-publication.ts, or
  release-declaration.ts (W09b's file, untouched as instructed).

src/__tests__/helpers/factory-s3-publication-suite.ts (shared W08 test fixture; +103/-2 lines):
  Rewired the shared S3 publication conformance suite to build S3FactoryManifestReleaseProfile with
  FactoryVerifiedAttemptMaterials instead of the fixture-only attempt-bound FactoryAttemptMaterials.
  This means every existing resolve/prepare/claim/dispatch/reconcile scenario in the suite --
  including the real-Postgres-and-S3 producer -- now proves the production-composable path, not a
  test-only shortcut. Also added four new tests:
    - exact listing for the named attempt; refusal by name of an unknown attempt id and of the real
      attempt under a mismatched tenant/project/run; no standing grant across a second, independently
      constructed instance; cancellation honored before any database round trip (a poisoned database
      double proves the abort short-circuits ahead of the first read).
    - an unsealed material is listed (visible) but never accepted by the profile
      (factory_s3_profile_invalid).
    - a lost materials response is safe to retry: a first resolve() whose materials.list() throws
      rejects cleanly, and a second resolve() on the same input reproduces the exact request and
      destination the healthy path would have produced.
    - prepare() revalidates the exact resolved input in its own final transaction (freeze section 5):
      a FactoryReleasePreparation whose profileInput.acceptedManifest is swapped after resolve is
      refused by prepare() with factory_release_profile_stale; the untampered preparation still
      commits.

    build()-shaped profiles; S3FactoryManifestReleaseProfile already implements resolve() natively,
    so it needs no lifting -- the standing ruling "the s3 destination kind maps to the manifest
