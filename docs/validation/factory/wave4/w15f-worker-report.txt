FIX
  lockRunFence raises FactoryRunEpochStaleError (a FactoryAttemptLivenessError, same code and message) with run,
  attempt, and both epochs. The usage-reconciliation step marks the hold once in the new nullable
  factory_budget_reservations.epoch_stale_json (migration add-factory-usage-epoch-stale, mirrored in factory-schema.ts)
  and reports one FactoryUsageHoldEpochStaleError (factory_usage_hold_epoch_stale) naming reservation, run, attempt,
  and both epochs. The uncertain-hold scan skips a hold marked at the current installation epoch (IS DISTINCT FROM,
  so an unreadable mark is retried and reported). The hold stays uncertain. A hold settled before the mark is not
  marked and its refusal is reported as it came. The mark is on the hold, not the run: a signed restore rebinds the
  run into the new epoch; only the old attempt's authority is left behind.
  Found on the way: the first commit attempt failed on real PostgreSQL only; a text parameter cast to jsonb arrived
  as a JSON string, so the scan could not read the mark and hid the hold. Fixed (jsonb_build_object, typed values)
  and pinned by a case that fails on the old comparison.
  Shared test helper src/__tests__/helpers/factory-attempt-fixtures.ts (the journal suite now uses it).
