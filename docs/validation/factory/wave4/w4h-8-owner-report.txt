Root cause
- Spec-level: the Podman runner read guest out/err FIFOs with FileHandle.createReadStream; each idle read held a Bun file-I/O pool
  thread (pool = CPU count). Two live workers on 4 vCPUs froze every guest. Proof: probe1/lane.log, probe1-instrumentation.patch,
  exp/fifo-pool.ts, exp/fifo-alt2.ts. Fixed by W4H-6 (merged). Independent second implementation kept only on
  proof/w4h-8-dup-transport (b455014f4), not in the head.
- W4H-8's defect: a delivery lease (60 s from claim) was never renewed while its handler ran, so a handler inside its own 60 s
  invocation deadline (which starts later) settled after its lease -> delivery_lease_lost; and each 1 s tick waiting on one failed
  drain logged it again (63 hosted lines = one failure).
