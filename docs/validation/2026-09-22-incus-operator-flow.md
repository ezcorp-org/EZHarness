# Incus operator setup flow — validation record

The admin-only screen at `/extensions/incus-setup` now discovers active, approved Incus releases, saves a host-generated client identity and deterministic server plan, shows the exact digest and command list, applies only that reviewed plan over pinned SSH, records a durable receipt, and offers a read-only mTLS provider probe after server verification. The browser cannot select SSH files, endpoints, commands, or private keys. A connection key is encrypted by the existing provider-connection store and bound to its approved release.

The first recipe is pinned to `sandbox-server` and now uses a Btrfs pool and 20 GiB root disk that match the advertised Incus presets. It is a loop-backed development recipe. The setup transport has a 60-second command deadline and a 1 MiB combined output bound; an uncertain result enters reconciliation. A process restart changes an unfinished apply to `reconcile_required` for the single-control-plane deployment. The saved plan and provider generation are checked again before execution. A newer saved plan replaces an older one, and a database constraint permits only one active apply per provider installation. An already observed matching step is skipped on retry.
