## Compiled filter repair and remaining audit-log check

The bundled seccomp compiler consumes the opening `[` before checking the syscall names array, so it skips every rule. Two independent actual C/libseccomp compilations report `added=0`; the 48-byte output matches the production image byte for byte. Its default action is correctly `ERRNO(38)`, so it denies all calls. With the proper sandbox context and inherited filter descriptor, the MCP probe exits 139 before producing output.

The prior gated test omitted database setup, the production sandbox context, and descriptor inheritance. It did not assert child exit or syscall output. Its expectation that `ptrace` is denied also conflicts with the declared profile, which uses the allow-and-log action for that call. The initial failure was not evidence of a journal problem. The repaired parser retains the array delimiter and adds 333 rules; 74 syscall names are unavailable on this architecture. Independent actual C/libseccomp builds and a regression that fails against the old parser confirm the fix.

Final image `abc3644405188068cb2b0397f85199799b76d51336cb8d17e0a0d83492189962`, digest `sha256:687e142a8bddaaae3889d08b9ee06e67cc6e0263dd1893861c0c6f3340ed3449`, contains the 2,736-byte filter with SHA-256 `4b9755245461ac5e8bed6bd3b9c3933faebd6cbc2638e50bbf6920d98efa2a1a`. Its Docker health check is present. The build, eight production checks, package import, Docker load, and clean 12-case browser flow all pass.

The actual filtered child in the preceding image `8f722e76` exits successfully: declared `getpid` returns 90 with errno 0, and absent `io_uring_setup` returns -1 with errno 38. This uses an owned image, an explicit bwrap capability fixture, production descriptor handoff, and a read-only compiled probe. The unfiltered control returns errno 14 for the same invalid, non-allocating call. These results prove syscall effects under the selected filter. Its compiler, profile, spawn code, and BPF bytes are unchanged in the final image; its packaging check confirms the same BPF digest.

The whole opted-in test remains **0 passed, 1 failed, 7 assertions** because no matching kernel audit rows are available. Both normal and elevated journal reads return no entries in the probe window. A platform owner must run the retained replay on an isolated Linux runner that supplies seccomp audit records. Log emission, ingestion, and PID attribution remain unproved. The separate extension-runner container profile is a distinct boundary. See the [parent seccomp review](validation/extension-v4-independent/parent/seccomp-final-independent-review.json).
